# イベント配信と永続ジョブの将来設計

## Gatewayの定期照合と並列配信

最後の通知の欠落も検知できるよう、進行中の局面を定期照合する。
配信を並列化する際は、取得・担当管理・順序保証を設計する。

## 他の永続処理への拡張

Consumer別のPostgreSQLジョブと完了状態を設ける。
処理ごとに受入・完了・一意性の範囲を設計する。

## DB境界をまたぐ受入と完了

別DB境界では、送信元の専用Outboxから受信側の永続Inboxへ同じIDで渡す。
受信側はInboxとジョブを原子的に保存し、その耐久的な受入後に確認を返す。
送信側は確認後にだけ、その宛先への受入済み状態を記録する。

この受入済み状態は業務処理の完了と区別し、一時通知用の受入状態とは共有しない。
Pub/Subの購読を永続ジョブへの中継元にしない。

別DB境界の完了記録は業務Commit後に行う。
再試行は業務側の一意制約・適用台帳でも冪等にする。
