# 対局イベントを受理時に確定し、一時通知と永続処理を分ける

受理した操作とイベントの解釈を保存側へ分散させないため、イベントの生成は対局操作を受理する側が所有する。
受理記録と通知対象を原子的に保存し、対局操作だけが確定して通知対象が欠落する状態を防ぐ。
保存形式と通信形式を分け、配信時に後の対局履歴からイベントを解釈し直す構成は採用しない。

対局の受理を通知先の稼働状態から独立させるため、通知は別プロセスで配信する。
一時通知の受入と購読者の業務処理完了は異なるため、同じ状態で管理しない。
永続処理を導入する際は、通知の購読状態に依存せず、耐久的な受入と業務側の冪等性を設計する。
具体案は[イベント配信と永続ジョブの将来設計](../design/event-processing-plan.md)に記録する。
