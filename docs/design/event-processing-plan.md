# イベント配信と永続ジョブの将来設計

## ゲートウェイの定期照合と並列配信

最後の通知の欠落も検知できるよう、進行中の局面を定期照合する。
配信を並列化する際は、取得、担当管理、順序保証を設計する。

## 他の永続処理への拡張

処理側ごとに PostgreSQL のジョブと完了状態を設ける。
処理ごとに受け入れ、完了、一意性の範囲を設計する。

## DB 境界をまたぐ受け入れと完了

別 DB 境界では、送信元の専用 Outbox から受信側の永続 Inbox に同じ ID で渡す。
Outbox は送信待ちのデータ、Inbox は受信済みのデータを保存する。
受信側は Inbox とジョブを原子的に保存し、永続的な受け入れの後に確認を返す。
送信側は確認後にだけ、その宛先への受け入れ済み状態を記録する。

この受け入れ済み状態は業務処理の完了と区別し、一時通知用の受け入れ状態とは共有しない。
Pub/Sub の購読を永続ジョブへの中継元にしない。

別 DB 境界の完了記録は、業務処理のコミット後に行う。
再試行は、業務側の一意制約や適用台帳でも冪等にする。
