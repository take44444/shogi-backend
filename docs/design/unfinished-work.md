# 未完成の機能と未検証の範囲

## 対局ルール

千日手、連続王手の千日手、入玉宣言勝ち、時計・時間切れの判定は未実装である。
王手でない合法手なし局面を扱う追加の終局制度も設けていない。

## 接続・認証・対局基盤

Realtime Gateway は認証済み WebSocket で着手・投了・更新受信を扱い、公開対局のログイン済み観戦者を許可する。
Cookie のセッションを User Service の `/me` で確認し、認証済み UserId で内部 Game API を呼ぶ。
Shard、Lease・Fencing、Game Router、定期的な進行中の局面照合、匿名観戦、Presenceは未実装である。

マッチメイキングは既存writer内の定期処理で実装した。状態回復、全ルール共通の同時参加制限、保存済みレートによる選択を扱う。
待機件数が多い場合の検索コスト、共通ロックの競合、終端チケット履歴の容量は未検証である。

## ユーザー管理

アカウント削除、管理者操作、既存アカウントの連携、全端末ログアウトは未実装である。
期限切れのログイン試行やセッションを定期的に掃除する常駐処理は導入していない。

## イベント配信と永続処理

Gateway 配信と、検出した欠落・購読断で接続を閉じて再接続時に保存済み局面を取得する仕組みは実装した。
最後の通知だけが欠落し、後続通知も切断検知もない場合の自動検出は未実装である。
待機系の自動昇格、並列配信、Publisherの高可用性、配信済み行の掃除は未実装である。
2種類の持ち時間に対応するElo更新、専用の永続ジョブ、匿名で取得できるユーザー別レートAPIは実装した。
時計・時間切れ判定、AI解析、他の処理向けの永続ジョブは未実装である。
導入時の方針は[イベント配信と永続ジョブの将来設計](event-processing-plan.md)を参照する。

## 運用の検証範囲

Realtime Gateway の接続数・メッセージサイズ・キュー件数などの上限は、性能測定に基づく値ではなく、資源保護のための初期値である。
Gateway の初版設計文書を作成した時点では、性能検証と本番ネットワークの検証は行っていない。

リポジトリの検査はCompose構成と初期化SQLの権限を対象とする。
本番環境のネットワーク分離、TLS終端、プロキシ設定の検証は別途必要である。
自動テストは実Googleアカウントによるログインの継続的な可用性を保証しない。
確認実績と再実行手順は[user-serverの検証手順](../../apps/user-server/README.md#verification)に置く。
