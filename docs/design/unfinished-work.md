# 未完成の機能と未検証の範囲

## 対局ルール

千日手、連続王手の千日手、入玉宣言勝ち、時計と時間切れの判定は未実装である。
王手されておらず合法手がない局面を扱う、追加の終局制度も設けていない。

## 接続・認証・対局基盤

リアルタイムゲートウェイは、認証済み WebSocket で着手、投了、更新受信を扱い、ログイン済みユーザーの公開対局の観戦を許可する。
Cookie のセッションを `user-server` の `/me` で確認し、認証済みの `UserId` で内部の対局 API を呼び出す。
対局の分割配置、処理権の期限管理と古い処理権の排除、対局ごとの接続先の振り分け、
進行中の局面の定期照合、匿名観戦、接続状態の管理は未実装である。

マッチメイキングは、既存の書き込みプロセス内の定期処理で実装した。
状態の回復、全ルール共通の同時参加制限、保存済みレートによる選択を扱う。
待機件数が多い場合の検索コスト、共通ロックの競合、終端チケット履歴の容量は未検証である。

## ユーザー管理

アカウント削除、管理者操作、既存アカウントの連携、全端末ログアウトは未実装である。
期限切れのログイン試行やセッションを定期的に削除する常駐処理は導入していない。

## イベント配信と永続処理

ゲートウェイへの配信は実装した。
欠落や購読切断を検出すると接続を閉じ、再接続時に保存済み局面を取得する。
最後の通知だけが欠落し、後続通知も切断検知もない場合の自動検出は未実装である。
待機系の自動昇格、並列配信、配信プロセスの高可用性、配信済み行の削除は未実装である。
2 種類の持ち時間に対応する Elo 更新、専用の永続ジョブ、認証不要のユーザー別レート API は実装した。
時計と時間切れの判定、AI 解析、他の処理向けの永続ジョブは未実装である。
導入時の方針は[イベント配信と永続ジョブの将来設計](event-processing-plan.md)に記述する。

## 運用の検証範囲

リアルタイムゲートウェイの接続数、メッセージ容量、キュー件数の上限は、性能測定に基づく値ではなく、資源保護のための初期値である。
ゲートウェイの初版設計文書を作成した時点では、性能検証と本番ネットワークの検証は行っていない。

リポジトリの検査は、Compose 構成と初期化 SQL の権限を対象とする。
本番環境のネットワーク分離、TLS 終端、プロキシ設定の検証は別途必要である。
自動テストは、実際の Google アカウントによるログインの継続的な可用性を保証しない。
確認実績と再実行手順は [user-server の検証手順](../../apps/user-server/README.md#動作を検証する)に置く。
